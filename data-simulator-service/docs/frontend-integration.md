# 模拟源管理：前端开发与接口对接说明

适用模块：`data-simulator-service`。核对日期：2026年9月29日。

本文以当前后端实现为准，说明页面如何组织、字段如何填写、接口如何调用。页面布局和交互属于前端实现建议，不代表已经提供前端页面；接口路径、字段和校验规则为已实现约定。不限定前端框架，可接入现有项目的表格、表单、抽屉和请求封装。

## 1. 页面范围

实现一个“模拟源管理”页面，包含以下区域：

| 区域 | 内容 |
|---|---|
| 查询栏 | 模拟源名称、运行状态、查询、重置 |
| 工具栏 | 新建模拟源、刷新 |
| 分页列表 | 配置概要、最近一次运行状态、发送数量、操作 |
| 新建/编辑弹窗 | 基础配置、PDXP专用配置、报文长度预览 |
| 详情抽屉 | 完整配置、只读协议参数 |
| 运行历史抽屉 | 历次运行、统计、异常原因、执行配置快照 |

支持多个模拟源同时运行，包括PDXP/UDP、FEP/TCP混合运行。操作加载状态应按行管理，不要启动一行就锁住整张表。

当前没有文件上传、服务器文件浏览、批量启停、暂停续跑、运行中修改或WebSocket推送接口，页面不要展示这些可操作入口。文件路径使用文本输入，指向服务端机器上的文件，不是浏览器用户电脑上的文件。

## 2. 服务地址与请求封装

默认服务地址：`http://127.0.0.1:8085`，实际部署地址由前端环境配置或网关路由提供。所有接口前缀为 `/simulator`，不要发往原管理服务端口。

建议开发代理或网关把 `/simulator` 转发到新服务，并完整保留路径。后端没有额外配置跨域处理，浏览器跨端口直连可能受跨域限制，应优先通过同源代理对接。当前模块未新增登录接口，若现有网关要求鉴权，沿用项目已有请求头。

POST请求统一使用 `Content-Type: application/json`，字段使用驼峰命名。

成功响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": 12
}
```

没有返回数据的操作可能直接省略 `data`：

```json
{
  "code": 200,
  "message": "操作成功"
}
```

失败同时使用相应HTTP状态码和业务码，示例：

```json
{
  "code": 409,
  "message": "模拟源正在执行，请先停止"
}
```

| 情况 | 前端处理 |
|---|---|
| HTTP 200且`code=200` | 读取`data`，执行刷新等后续交互 |
| HTTP 400 | 展示后端`message`，保留用户填写内容 |
| HTTP 409 | 展示冲突原因，刷新当前记录；不能只依赖旧列表状态 |
| HTTP 500 | 展示后端错误说明，允许用户手动刷新 |
| 超时、网络断开、非JSON响应 | 提示“连接异常，操作结果待确认”，重新查询状态 |

不要盲目自动重试新建、启动、停止等写操作。响应丢失不代表后端没有执行，特别是启动请求超时后应先查详情和历史确认。

后端启用了未知字段校验。提交时应按请求字段白名单构造对象，不要直接把详情响应整体提交，也不要提交页面临时字段、中文名称、运行状态或统计字段。

## 3. 接口清单

| 方法 | 路径 | 用途 | 成功返回的`data` |
|---|---|---|---|
| GET | `/simulator/findData` | 枚举与默认参数 | 枚举对象 |
| GET | `/simulator/sources` | 分页列表 | 分页对象 |
| GET | `/simulator/sources/{id}` | 配置详情 | 完整配置对象 |
| POST | `/simulator/sources/create` | 新建 | 模拟源ID，数字 |
| POST | `/simulator/sources/update` | 完整修改 | 无 |
| POST | `/simulator/sources/delete` | 逻辑删除 | 无 |
| POST | `/simulator/sources/start` | 启动 | 本次运行ID，数字 |
| POST | `/simulator/sources/stop` | 停止指定运行 | 无 |
| GET | `/simulator/sources/{id}/runs` | 运行历史 | 分页对象 |

导入完整接口定义可使用同目录的 [apifox-openapi.json](apifox-openapi.json)。

## 4. 页面初始化与枚举

进入页面时请求 `GET /simulator/findData`，同时加载第一页列表。

枚举响应的 `data` 包含：

| 字段 | 结构 | 用途 |
|---|---|---|
| `protocols` | 协议选项数组 | 协议选择及默认值联动 |
| `statuses` | `{value,label}`数组 | 状态筛选，包含“未启动” |
| `yesNo` | `{value,label}`数组 | 是否循环选择 |

每个协议选项包含 `value`、`label`、`transferType`、`transferTypeName`、`defaultPort`、`defaultIntervalMillis`、`defaultLoopEnabled`。当前值如下，页面优先使用接口返回值：

| 协议 | `transferProtocol` | `transferType` | 默认端口 | 默认间隔 | 默认循环 |
|---|---|---|---|---|---|
| PDXP | 2 | 1（UDP） | 9001 | 500毫秒 | 1（是） |
| FEP | 3 | 2（TCP） | 19003 | 10毫秒 | 0（否） |

运行状态筛选的数字与响应中文对应如下：

| 查询参数`status` | 响应`runStatus` | 建议显示 |
|---|---|---|
| 0 | 未启动 | 灰色 |
| 1 | 启动中 | 蓝色、加载提示 |
| 2 | 运行中 | 绿色 |
| 3 | 停止中 | 橙色、加载提示 |
| 4 | 已停止 | 灰色 |
| 5 | 已完成 | 绿色 |
| 6 | 异常 | 红色 |

列表与历史直接返回中文 `runStatus`，不返回数字运行状态字段。筛选提交数字；界面状态判断可由枚举接口建立中文与数字的映射，不要读取不存在的 `statusCode` 或 `latestStatus`。

## 5. 列表查询与展示

请求示例：

```text
GET /simulator/sources?name=遥测&status=2&pageNum=1&pageSize=20
```

| 查询参数 | 是否必填 | 规则 |
|---|---|---|
| `name` | 否 | 名称包含查询；清空时不传 |
| `status` | 否 | 0～6；“全部”时不传；注意0是有效筛选值 |
| `pageNum` | 否 | 默认1，最小1 |
| `pageSize` | 否 | 默认20，范围1～100 |

查询条件变更后把页码重置为1。列表当前固定按ID倒序排列，没有自定义排序参数。

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "pageNum": 1,
    "pageSize": 20,
    "total": 1,
    "records": [
      {
        "id": 12,
        "sourceName": "遥测模拟源一",
        "transferProtocol": 2,
        "transferType": 1,
        "filePath": "D:/模拟数据/telemetry.dat",
        "targetHost": "127.0.0.1",
        "targetPort": 9001,
        "sendIntervalMillis": 500,
        "loopEnabled": 1,
        "remark": null,
        "createTime": "2026-09-29T09:00:00",
        "updateTime": "2026-09-29T09:00:00",
        "pdxp": null,
        "latestRunId": 101,
        "sentUnitCount": 20,
        "protocolName": "PDXP",
        "transferTypeName": "用户数据报传输",
        "loopEnabledName": "是",
        "runStatus": "运行中"
      }
    ]
  }
}
```

列表建议列：名称、协议、目标地址/端口、文件路径、发送间隔、是否循环、状态、本次发送单元数、操作。名称和文件路径支持省略与完整提示。

重要说明：

- 列表中的 `pdxp` 不加载协议参数，即使该行是PDXP也可能为 `null`；不能据此判断“没有配置”。
- `sentUnitCount` 是当前或最近一次运行的计数，不是该源历次运行总和。未启动时为0。
- PDXP可将计数标注为“帧”；FEP标注为“数据单元”，不能标成文件数量。
- `latestRunId` 为最近一次运行ID，可能为 `null`；停止操作需要它。
- 列表不含发送字节数、完整轮数或异常原因，需要从运行历史查询。

## 6. 新建与编辑表单

### 6.1 基础配置

| 字段 | 控件建议 | 规则 |
|---|---|---|
| `sourceName` | 文本框 | 必填，去首尾空格，最多100字符；名称冲突以服务端返回为准 |
| `transferProtocol` | 下拉框 | 必填；新建可选，编辑禁用 |
| `transferType` | 只读展示 | 随协议确定，不能任意组合 |
| `filePath` | 文本框 | 必填，最多1000字符，服务端本地路径 |
| `targetHost` | 文本框 | 必填，最多100字符，默认127.0.0.1；不应只允许IPv4格式 |
| `targetPort` | 整数输入 | 1～65535，按协议填默认值 |
| `sendIntervalMillis` | 整数输入 | 0～86400000，单位毫秒；0表示连续发送 |
| `loopEnabled` | 开关或单选 | 提交数字0/1，不提交布尔值或中文 |
| `remark` | 多行文本 | 可选，最多500字符 |

建议前端展示并提交所有上述可编辑字段，不依赖省略字段恢复默认值。端口、间隔和长度都提交JSON数字，不提交带单位的字符串。

选择协议后填入对应默认端口、发送间隔、循环设置，切换PDXP配置区域。只在新建协议切换时应用默认值，不要在编辑详情回填后又覆盖用户原有配置。切换协议会重置相关配置时，应在交互上明确提示。

### 6.2 PDXP四种长度

下面所有字段位于请求的 `pdxp` 对象内，都是每个模拟源独立配置。

| 字段 | 页面名称 | 默认值 | 校验 |
|---|---|---|---|
| `inputFrameLength` | 输入帧长度 | 512 | 整数，1～65475字节 |
| `transportHeaderLength` | 传输头长度 | 2 | 整数，0～65475字节 |
| `telemetryHeaderLength` | 原帧头长度 | 4 | 整数，0～输入帧长度 |
| `customDataLength` | 自定义数据长度 | 5 | 整数，0～65475字节 |

表单旁实时显示：

```text
原帧剩余部分长度 = 输入帧长度 - 原帧头长度
PDXP数据域长度 = 输入帧长度 + 自定义数据长度
UDP报文总长度 = 传输头长度 + 32 + 自定义数据长度 + 输入帧长度
```

最终总长度必须不超过65507字节。仅满足各字段的单独范围还不够，保存前必须执行组合校验。

报文预览顺序固定为：

```text
传输头 → 32字节PDXP包头 → 自定义数据 → 原帧剩余部分 → 原帧头
```

原帧头来自输入文件并移到末尾，不需要用户填写原帧头内容，也不额外计入报文总长度。32字节PDXP包头长度固定，不提供编辑框。前端只计算和展示长度，不拼装真实报文。

默认值的预览为 `2 + 32 + 5 + 508 + 4 = 551字节`。

### 6.3 PDXP十六进制内容

| 字段 | 页面名称 | 默认值 | 所需字符数 |
|---|---|---|---|
| `transportHeader` | 传输头内容 | `1234` | `transportHeaderLength × 2` |
| `customData` | 自定义数据内容 | `0102030405` | `customDataLength × 2` |
| `ver` | 版本 | `80` | 2 |
| `mid` | 任务标志 | `0001` | 4 |
| `sid` | 信源地址 | `00000001` | 8 |
| `did` | 信宿地址 | `00000001` | 8 |
| `bid` | 数据标志 | `00000001` | 8 |
| `initialNo` | 包序号初值 | `00000000` | 8 |
| `flag` | 数据处理标志 | `00` | 2 |

内容输入框使用字符串，保留前导零。只允许0～9、A～F、a～f，不接受 `0x` 前缀、空格、逗号或换行；可转为大写后提交。不要使用数字输入框。

传输头或自定义数据长度为0时，对应内容必须提交空字符串 `""`，不能提交 `null`。长度变更后重新校验内容，不能静默截断或补零修改用户填写的内容。

各字段由后端独立按小端写入，前端无需逆序。例如传输头填写 `1234`，发送字节为 `34 12`。原文件数据只移动位置，不由前端进行字节反转。

日期、时标、保留字段和数据域长度自动生成，不设置用户输入项。包序号每次启动从 `initialNo` 开始，循环读文件时继续递增。

### 6.4 FEP表单

FEP只显示基础配置，隐藏并从提交对象中移除整个 `pdxp` 字段。不能仅隐藏控件却提交旧的PDXP对象，否则后端返回400。

FEP分块大小、连接超时和应答超时由Nacos配置维护，仓库配置文件位于根目录 `nacos-config/data-simulator-service.yaml`，发布配置后重启服务生效。当前表单不编辑这些值。默认分别为4096字节、5000毫秒和10000毫秒，实际执行值可在运行快照的 `fep` 对象查看。

FEP无需512字节对齐，支持空文件；文件长度上限为2147483647字节。开启循环代表完整文件交换成功后再次发送，接收端可能因文件已存在而不重复接收数据。接收端需使用匹配的分块长度。

### 6.5 文件检查时机

前端无法直接检查服务端文件是否存在。保存成功只代表配置通过校验，不代表文件能发送。后端在启动时检查文件存在、可读及协议约束；PDXP文件必须非空且大小为配置输入帧长度的整数倍。

建议文件路径下方提示：“请填写模拟源服务所在机器上的文件路径，启动时检查文件是否可用。”

## 7. 保存请求示例与编辑流程

### 7.1 新建PDXP

`POST /simulator/sources/create`，不传 `id`：

```json
{
  "sourceName": "遥测模拟源一",
  "transferProtocol": 2,
  "transferType": 1,
  "filePath": "D:/模拟数据/telemetry.dat",
  "targetHost": "127.0.0.1",
  "targetPort": 9001,
  "sendIntervalMillis": 500,
  "loopEnabled": 1,
  "remark": "本地遥测联调",
  "pdxp": {
    "inputFrameLength": 512,
    "transportHeaderLength": 2,
    "telemetryHeaderLength": 4,
    "customDataLength": 5,
    "transportHeader": "1234",
    "customData": "0102030405",
    "ver": "80",
    "mid": "0001",
    "sid": "00000001",
    "did": "00000001",
    "bid": "00000001",
    "initialNo": "00000000",
    "flag": "00"
  }
}
```

### 7.2 新建FEP

```json
{
  "sourceName": "文件模拟源一",
  "transferProtocol": 3,
  "transferType": 2,
  "filePath": "D:/模拟数据/example.dat",
  "targetHost": "127.0.0.1",
  "targetPort": 19003,
  "sendIntervalMillis": 10,
  "loopEnabled": 0,
  "remark": "文件交换联调"
}
```

新建成功后提示“配置已保存”，关闭弹窗并刷新列表，不自动启动。若产品另加“保存并启动”按钮，应明确分为保存和启动两次请求，并分别处理结果。

### 7.3 编辑

1. 点击编辑后请求 `GET /simulator/sources/{id}`，不要直接从列表行回填PDXP参数。
2. 查询成功后按可编辑字段白名单回填；详情中的 `pdxp.sourceId` 是关联字段，不回传。
3. 锁定协议选择框，运行状态属于活动状态时不允许编辑。
4. 提交 `POST /simulator/sources/update`，请求与对应新建示例相同，但必须增加顶层 `id`。
5. 更新是完整替换可编辑配置，不是局部补丁。所有当前配置都应提交；省略可选字段可能恢复默认值，尤其不能漏掉整个 `pdxp` 对象。
6. 成功后关闭弹窗并刷新。若编辑期间被其他页面启动，后端会拒绝更新，保留表单并提示刷新。

不要把 `protocolName`、`transferTypeName`、`loopEnabledName`、`runStatus`、`latestRunId`、`sentUnitCount`、`createTime`、`updateTime` 或页面预览字段放入保存请求。

## 8. 行操作与状态控制

| 当前状态 | 启动 | 停止 | 编辑 | 删除 | 详情/历史 |
|---|---|---|---|---|---|
| 未启动 | 可用 | 禁用 | 可用 | 可用 | 可用 |
| 启动中 | 禁用 | 可用，有运行ID时 | 禁用 | 禁用 | 可用 |
| 运行中 | 禁用 | 可用，有运行ID时 | 禁用 | 禁用 | 可用 |
| 停止中 | 禁用 | 禁用，等待刷新 | 禁用 | 禁用 | 可用 |
| 已停止 | 可用 | 禁用 | 可用 | 可用 | 可用 |
| 已完成 | 可用 | 禁用 | 可用 | 可用 | 可用 |
| 异常 | 可用 | 禁用 | 可用 | 可用 | 可用 |
| 连接异常/状态无法确认 | 暂禁用 | 暂禁用 | 暂禁用 | 暂禁用 | 可展示缓存并标记过期 |

“状态无法确认”是前端网络异常提示，不是后台新增枚举值，不能作为 `status` 筛选值提交。按钮状态仅作交互引导，最终以后台校验为准。

### 8.1 启动

请求 `POST /simulator/sources/start`：

```json
{ "id": 12 }
```

返回的 `data` 是本次运行ID，例如101，不是模拟源ID。

点击后立即给该行加请求锁，防止重复点击。成功后记录运行ID并立即刷新详情/列表，再通过轮询确认状态。启动成功只表示任务已提交，TCP连接失败等后续问题仍可能使状态变成“异常”。

新一轮运行计数归零，历史记录保留。默认服务并发上限为16，超过上限后端返回409，前端展示后端提示，不把记录强行标为运行中。

### 8.2 停止

请求 `POST /simulator/sources/stop`：

```json
{ "id": 12, "runId": 101 }
```

`runId` 使用当前详情/列表中的 `latestRunId` 或刚刚启动返回的运行ID。行数据更新时同步更新该值，不能一直缓存旧运行ID。缺少运行ID时先查询详情再决定是否发送。

成功后提示“停止请求已提交”，继续刷新直到“已停止”或其他终态，不要把HTTP成功直接当作资源已经释放。旧运行的停止请求不会停止新一轮运行，因此收到成功也仍需刷新实际状态。

### 8.3 删除

请求 `POST /simulator/sources/delete`：

```json
{ "id": 12 }
```

建议二次确认：“删除此模拟源配置？历史运行记录仍保留。”删除成功后刷新当前页；若该页为空且页码大于1，回退上一页再查询。删除只影响配置列表，不关闭接收端。

## 9. 轮询、并发请求和网络异常

后台约每2秒保存一次统计，页面建议在可见状态下每2～3秒刷新列表；后台终止运行时还会保存最终统计。

实现建议：

1. 上一次查询完成后再安排下一次查询，避免慢请求堆积。
2. 翻页或修改筛选时取消旧请求，或使用请求序号忽略过期响应，防止旧列表覆盖新条件结果。
3. 页面隐藏、组件卸载时停止定时器；重新可见时立即刷新。
4. 页面已有编辑弹窗时，轮询只更新列表，不能覆盖弹窗中的未保存输入。
5. 发起操作后立即刷新，再保留短暂的本地“状态确认中”，避免统计保存延迟导致按钮重新可点。
6. 刷新失败保留上次数据并标记过期，显示最后更新时间；不能把所有实例改成“已停止”。
7. 不要因当前页没有运行实例就永久停止刷新，否则无法感知其他页面发起的操作。

没有专门的实时状态接口，列表、详情和运行历史反映最近保存的数据库状态，不是毫秒级实时消息。

## 10. 运行历史与详情

请求：

```text
GET /simulator/sources/12/runs?pageNum=1&pageSize=20
```

分页结构同列表，记录按运行ID倒序排列。没有历史时间范围、状态筛选或独立单次运行详情接口。

每条历史记录字段：

| 字段 | 展示含义 |
|---|---|
| `id` | 运行ID |
| `sourceId` | 模拟源ID |
| `runStatus` | 中文状态 |
| `startTime`、`endTime` | 开始、结束时间；结束时间可空 |
| `sentUnitCount` | 已发送帧或文件数据单元数，FEP包括结束空单元 |
| `sentByteCount` | 已发送应用层协议字节数，FEP包括请求包，不含网络层头 |
| `completedLoopCount` | 完成文件读取或文件交换轮数 |
| `lastSendTime` | 最近发送时间，可空 |
| `errorMessage` | 中文异常原因，可空 |
| `configSnapshot` | 本次执行时配置，已经是JSON对象 |
| `createTime`、`updateTime` | 记录创建与更新时间 |

`configSnapshot` 不需要再执行字符串JSON解析。展开后以只读方式展示 `source`；FEP还会有 `fep.dataUnitLength`、`fep.connectTimeoutMillis`、`fep.responseTimeoutMillis`。PDXP四种长度位于 `configSnapshot.source.pdxp`。

快照代表执行时的配置，不能使用当前配置替代。快照内可能包含辅助展示字段，历史行状态以记录顶层的 `runStatus` 为准，不能读取快照内的状态。不要把快照直接提交给更新接口。

统计说明建议放在提示中：UDP发送成功不等于接收端收到；FEP文件已存在时可能完成一轮但没有发送新的文件数据单元，不能用轮数推算新增接收文件数。

时间是服务端本地时间字符串，不含时区偏移。按项目约定的服务端时区展示，不要擅自追加 `Z` 按UTC转换。空结束时间、空错误说明显示“—”，数字0正常显示。

## 11. 前端开发拆分建议

| 模块 | 职责 |
|---|---|
| 模拟源请求封装 | 统一9个接口、响应解包、错误提示和请求取消 |
| 列表页面 | 查询、分页、轮询、行级操作锁 |
| 配置表单 | 新建/编辑模式、字段白名单提交、协议联动 |
| PDXP配置区域 | 四种长度、十六进制字段、组合校验和报文预览 |
| 详情抽屉 | 实时查询完整配置、只读展示 |
| 历史抽屉 | 分页记录、异常说明和配置快照 |

沿用已有项目的组件和请求工具，不需要为此引入新的前端状态管理或图表依赖。表单对象与列表响应对象分开维护，便于避免把只读字段提交给后端。

## 12. 联调验收清单

- PDXP新建后能查详情，四种长度和十六进制内容准确回显。
- FEP切换后不提交残留PDXP字段；编辑已有源不能切换协议。
- 编辑自定义长度配置再保存，原长度不会被默认值覆盖。
- 修改长度会触发内容长度和总报文长度校验，前端不会擅自补零或截断。
- 长度为0时内容可为空字符串；原帧头长度不能超过输入帧长度。
- 列表没有PDXP参数时，编辑仍能通过详情正确回填。
- 状态筛选提交数字，未启动值0不被当成空条件丢掉；显示使用中文状态。
- 两个源可并发启动；操作加载状态按行隔离；停止一个不会改变另一行的运行状态。
- 停止携带正确运行ID，旧页面操作后会刷新真实状态。
- 运行中不能编辑/删除；重复启动、名称冲突能显示409提示。
- 不存在的源文件可以先保存配置，但启动失败时能准确提示。
- 单次发送正常完成后显示“已完成”；发送失败后可查看异常说明。
- 页面切换或隐藏后不遗留轮询，旧查询响应不会覆盖新筛选结果。
- 服务不可达时显示状态待确认，不显示虚假的“已停止”。
- 删除后列表刷新正确，已打开的历史仍可按模拟源ID查询。
