# 前端对接修改明细：采集接口列表统计

更新日期：2026-10-13

## 1. 涉及接口

`GET /collection/interfaces`

接口路径以项目现有请求基础地址为准，继续使用当前分页列表请求。

请求参数沿用现有定义：`taskId`、`interfaceType`、`transferType`、`status`、`enabled`、`pageNum`、`pageSize`。本次无需新增请求参数。

响应分页结构仍为 `data.pageNum`、`data.pageSize`、`data.total`、`data.records`。两个统计字段位于 `data.records` 的每条接口记录中。

## 2. 返回字段变化

| 字段 | 变更 | 类型 | 含义及页面展示 |
| --- | --- | --- | --- |
| `dataPacketCount` | 原字段调整数据来源 | 整数，后端为 int64 | 当前任务、当前接口的累计采集量。PDXP 为完整帧数，FEP 为完整文件数；没有统计时返回 `0`。建议列表列名使用“累计采集量”。 |
| `interfaceRateKbps` | 新增 | 数值，后端为 double | 当前接口最新采集速率，单位 `KB/s`，最多两位小数。无缓存、缓存过期、缓存内容无效或 Redis 不可用时返回 `0`。建议列表列名使用“采集速率”。 |

`interfaceRateKbps` 返回纯数值，例如 `128.5`。前端展示时追加单位，显示为 `128.5 KB/s`；不要再次除以 `1024`。

`dataPacketCount` 的计数单位与接口协议有关，不能统一解释为网络报文数量。一个报文包含多个完整 PDXP 帧时，按完整帧数量累计；FEP 文件分片不单独增加累计文件数。

## 3. 响应示例

下面仅列出分页信息及本次相关字段，实际响应还包含原有接口配置字段。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "pageNum": 1,
    "pageSize": 10,
    "total": 1,
    "records": [
      {
        "id": 11,
        "taskId": "TASK-20260908-001",
        "interfaceName": "遥测 UDP 接口",
        "transferProtocol": 2,
        "transferProtocolName": "PDXP",
        "status": 1,
        "statusName": "在线",
        "dataPacketCount": 25600,
        "interfaceRateKbps": 128.5
      }
    ]
  }
}
```

无统计数据或实时缓存时，对应字段返回：

```json
{
  "dataPacketCount": 0,
  "interfaceRateKbps": 0
}
```

## 4. 数据更新与展示规则

- 后端先查询采集接口分页结果，再批量查询当前页接口的采集量和速率，回填到分页响应。前端无需逐个接口请求统计。
- `dataPacketCount` 按任务和接口汇总 `collect_interface_statistics.collection_count`，包含逻辑删除的已归档统计窗口，累计量不因七天归档清理而减少。
- 采集量来自已入库统计，默认按五秒窗口入库后才能查询到新增数量，可能存在延迟，不要要求它与实时速率同步变化。
- 采集实时速率默认每秒刷新 Redis，任务下的实时采集缓存每次写入后设置五秒过期。前端需再次请求列表，才能看到刷新后的值。
- 速率为 `0` 时应正常显示 `0 KB/s`。它可能表示没有新流量，也可能表示没有有效缓存，不能用速率是否为 `0` 判断接口在线状态；在线状态继续使用 `status`、`statusName`。
- 切换任务、筛选条件或页码时，使用最新分页响应中的统计值更新列表。

## 5. 前端需要修改的内容

1. 在采集接口列表响应类型中补充数值字段 `interfaceRateKbps`。
2. 累计采集量列继续绑定 `row.dataPacketCount`，按本文件的新计数口径展示。
3. 增加采集速率列，绑定 `row.interfaceRateKbps`，追加 `KB/s` 单位，保留最多两位小数。
4. 无统计时显示 `0`，速率为零时显示 `0 KB/s`；兼容旧服务响应时，可为缺失字段设置零值兜底。
5. 如页面需要持续展示实时变化，沿用页面的刷新机制重新请求分页接口。
6. 更新 Apifox 接口定义，使用同目录下的 `apifox-openapi.yaml`。

## 6. 本次修改的接口范围

统计补充作用于 `GET /collection/interfaces` 分页列表。

`GET /collection/interfaces/{id}` 详情接口尚未接入本次统计补充：详情的 `dataPacketCount` 仍读取接口配置表，详情响应不返回 `interfaceRateKbps`。列表的累计采集量和采集速率应从分页列表响应取值。
