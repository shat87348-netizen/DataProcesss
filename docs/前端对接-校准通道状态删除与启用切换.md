# 校准通道前端对接说明

更新日期：2026-10-13。

本次删除校准通道的状态字段，保留启用开关，并新增独立的启用、禁用接口。检测算法和校准记录的数据结构不变。

## 一、前端需要修改的内容

| 位置 | 本次修改 |
|---|---|
| 校准通道列表 | 删除原“状态”列及对 `channelStatus`、`channelStatusName` 的依赖；启用开关使用 `enabled`。 |
| 新增、编辑表单 | 删除通道状态输入项，不再提交 `channelStatus`；保留 `enabled`。 |
| 校准通道详情 | 删除原状态展示；启用状态可展示 `enabledName`。 |
| 行内启用开关 | 调用新增的 `POST /calibration/channels/enabled`，无需提交完整的算法配置。 |
| 枚举加载 | `/calibration/findData` 不再返回 `channelStatus`；继续使用 `enabled` 枚举。 |
| 新增通道后的刷新 | 刷新通道列表和校准记录列表，创建通道时已经创建对应的初始校准记录。 |

删除的字段：

| 字段 | 原含义 | 当前处理 |
|---|---|---|
| `channelStatus` | 通道状态编码：0停止、1正常、2异常 | 新增、修改请求及列表、详情返回中删除。 |
| `channelStatusName` | 通道状态中文名称 | 列表和详情返回中删除。 |

保留的字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `enabled` | Integer | `0` 禁用，`1` 启用。前端提交数字，不提交布尔值或中文名称。 |
| `enabledName` | String | 启用状态中文名称：禁用、启用。用于查询结果展示，不作为保存参数。 |

## 二、新增启用、禁用接口

```http
POST /calibration/channels/enabled
Content-Type: application/json
```

鉴权方式沿用项目现有接口约定。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `taskId` | String | 是 | 当前页面选中的外部试验任务编号，不能为空或空白字符串。 |
| `id` | Long | 是 | 校准通道主键，大于0；必须属于该任务，并且未删除。 |
| `enabled` | Integer | 是 | `1` 启用，`0` 禁用；必须传目标状态。 |

启用示例：

```json
{
  "taskId": "728101",
  "id": 1,
  "enabled": 1
}
```

禁用示例：

```json
{
  "taskId": "728101",
  "id": 1,
  "enabled": 0
}
```

接口设置的是请求中的目标状态，不是把当前状态自动取反。重复提交相同目标状态可以正常保存。

### 成功返回

HTTP 200，响应体：

```json
{
  "code": 200,
  "message": "操作成功"
}
```

成功响应没有 `data` 字段，也不返回新的通道对象。前端不能以 `data` 是否存在或是否为 `true` 判断成功，应检查 `code`。

### 参数或业务校验失败

HTTP 400，统一返回 `code`、`message`。例如通道不属于当前任务：

```json
{
  "code": 400,
  "message": "当前试验任务下的校准通道不存在"
}
```

常见提示：

| 情况 | 提示 |
|---|---|
| 任务编号缺失或空白 | 试验任务编号不能为空 |
| 主键缺失 | 业务主键不能为空 |
| 主键不大于0 | 校准通道ID必须大于0 |
| 启用字段缺失 | 启用状态不能为空 |
| 启用字段为0、1以外的整数 | 启用状态只能为0或1 |
| 通道不存在或已删除 | 校准通道不存在 |
| 通道属于其他任务 | 当前试验任务下的校准通道不存在 |

开关请求期间应避免同一行重复提交；失败后恢复原开关值并展示后端提示。成功后重新查询当前任务的通道列表，使用返回的 `enabled` 和 `enabledName` 更新页面。

## 三、已有接口的变化

本次只新增一个启用切换接口。以下已有接口保留原有调用方式：

| 接口 | 本次变化 |
|---|---|
| `GET /calibration/channels?taskId=728101` | 返回对象移除 `channelStatus`、`channelStatusName`，其他字段保持不变。 |
| `GET /calibration/channels/{id}` | 返回对象移除上述两个字段，路径主键用法不变。 |
| `POST /calibration/channels/create` | 请求删除 `channelStatus`，仍支持 `enabled`；新增时不传 `enabled` 默认启用。 |
| `POST /calibration/channels/update` | 请求删除 `channelStatus`，仍支持 `enabled`；不传 `enabled` 保留原值。 |
| `GET /calibration/findData` | 返回数据移除 `channelStatus` 枚举项，其他枚举保持不变。 |
| `POST /calibration/channels/delete` | 本次未修改。 |
| 校准总览、校准记录列表及分页详情接口 | 本次未修改返回结构。 |

通道列表返回的相关字段示例（这里只展示与本次对接有关的字段，算法配置、时间等字段仍按原接口返回）：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "id": 1,
      "taskId": "728101",
      "channelName": "电压校准",
      "calibrationFormula": "1",
      "enabled": 1,
      "enabledName": "启用"
    }
  ]
}
```

`GET /calibration/findData` 中保留的 `enabled` 枚举为：

```json
[
  { "value": 0, "label": "禁用" },
  { "value": 1, "label": "启用" }
]
```

这段数组是 `data.enabled` 的内容，不是完整响应体。`detectMethod`、`dynamicUpdate`、`autoClean`、`isOutlier` 等原有枚举继续返回。

## 四、开关生效和校准记录规则

1. 处理模块按任务加载已启用、未删除的校准通道，使用 `calibrationFormula` 匹配遥测参数。
2. 启用、禁用保存后，管理服务通知处理模块刷新内存中的校准配置。同步成功后无需重启采集接口，后续处理的帧使用刷新后的配置。
3. 禁用后，后续帧不再使用该通道执行野值检测；历史校准记录、累计野值数量及详情保留，不清零、不删除。已经在处理或等待落库的详情仍可能完成写入。
4. 启用后仍需满足任务级 `parameterRangeCheckEnabled=1`，并且遥测参数的校准公式与通道公式匹配，才会进行野值检测。任务总开关关闭时，单独启用通道不会产生新的检测结果。
5. 检出的野值详情按现有规则每5秒批量入库，因此记录数量不一定在切换开关后立即变化。只记录检出的野值详情，正常值不产生详情。
6. 新增通道会同时创建一条累计野值数量为0的校准记录。新增成功后刷新通道列表及校准记录列表；切换启用状态不会重新创建汇总记录。
7. 修改配置只影响后续处理，不会自动补检历史数据。

前端无需额外调用采集接口停用、启用来刷新校准配置。内部同步失败会记录到操作日志和告警；保存接口没有返回独立的运行配置同步结果字段，通道列表展示的是数据库中的启用配置。

## 五、前端验收清单

- 新增、编辑、详情和列表中不再使用 `channelStatus`、`channelStatusName`。
- 枚举加载不再依赖 `data.channelStatus`。
- 行内开关请求正确携带当前任务编号、通道主键和数字形式的目标启用值。
- 启用、禁用成功后刷新通道列表，失败后恢复原开关状态。
- 禁用通道后已有校准记录和累计数量仍可显示。
- 新增通道成功后刷新校准记录列表，即使野值数为0也展示对应记录。
- 启用但任务总开关关闭时，不将“暂无野值详情”视为保存失败。
