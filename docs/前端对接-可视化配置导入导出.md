# 可视化配置导入导出对接

导入导出的是当前用户在指定试验任务下的整页配置，包含所有显示和隐藏组件。所有接口都使用现有登录令牌；用户归属由后端确定。

## 导出

调用`GET /visualization/config/export?taskId=目标任务编号`，成功响应为JSON文件附件，不是`code/message/data`结构。前端按文件下载处理，可使用固定下载名称“可视化配置.json”。错误响应仍是现有统一错误结构，应判断响应状态及内容再下载。

导出的参数筛选仅包含各个实时数据、实时曲线组件已经勾选的参数。后端直接读取组件场景勾选记录，直接通过筛选树勾选而没有数据项记录的参数也会导出。同一参数在不同组件内分别保存。文件不包含未勾选遥测参数、实时数值、告警记录、图片或文件实体，也不包含源数据库主键。

布局使用现有`gridX/gridY/gridWidth/gridHeight`网格单位；不会转换成像素。非遥测数据项保留原勾选状态；已勾选参数已有的数据项放在该参数的`dataItems`中。目前未持久化的搜索文本、表格列宽和排序不在导出范围内。

## 导入流程

1. 选择目标任务及本系统导出的`.json`文件，保留所选文件对象。
2. 调用`POST /visualization/config/import/preview?taskId=目标任务编号`，请求体为表单，文件字段名称为`file`；不手工设置带边界的请求头。
3. 展示待导入组件数、勾选参数数、已有数据项数和将被替换的原组件数。`data.valid=false`时展示中文`errors`并禁止导入；修改文件或目标任务后重新检查。
4. 明确提示“导入将替换当前用户在此任务下的全部可视化配置”。文件组件数为零时提示“将清空当前页面配置”。用户确认后重新上传同一文件，调用`POST /visualization/config/import?taskId=目标任务编号`。
5. 后端会重新检查最新关联；失败时展示中文错误，原配置保持完整。检查通过不代表后续写入必然成功。
6. 导入成功后重新调用`GET /visualization/widgets?taskId=目标任务编号`，清理旧组件主键缓存，使用新组件主键加载筛选树及业务数据。旧组件主键已经失效。

## 文件规则

文件最大10MB，最多500个组件，参数勾选和已有数据项合计最多50000条。文件必须显式提供第一版版本号及组件数组；组件数组可以为空，不能缺失或为`null`。可选列表省略时视为空数组，显式`null`不允许。重复字段、未知字段、非整数布局、重复组件标识、组件内重复参数、非法类型或布局都会阻止导入。

参数按“设备卫星类型＋设备卫星编码＋遥测代号”精确匹配目标任务内的有效参数，不按名称或旧主键回退匹配。设备名称、遥测名称、系统路径及中文枚举名称供展示核对，不参与定位。现有组件和设备类型枚举编码继续沿用。

已有数据项的可选接口、协议关联按目标任务内唯一的有效名称重新匹配；名称缺失或重名都阻止导入。没有关联时字段可以省略或为`null`，不能传空白文本。已勾选参数的数据项`selected`必须为`true`。

导出也会检查源任务中的参数及接口、协议关联，存在失效关联或引用名称重名时提示修正，保证下载的文件能在源任务原样恢复。

后端只替换当前登录用户的目标任务组件及组件勾选，不替换遥测解析配置、采集接口、协议配置，也不修改其他用户或固定处理后数据页面的勾选。所有删除和新增均在同一事务中完成。

## 文件样例

以下是标准JSON，可以直接作为配置文件；该样例需要目标任务内存在类型为卫星、编码为“卫星A”、遥测代号为“T001”的有效参数。

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-10-13T09:00:00+08:00",
  "widgets": [
    {
      "widgetKey": "temperature-table",
      "widgetType": 2,
      "widgetTypeName": "实时数据",
      "widgetTitle": "温度表格",
      "gridX": 0,
      "gridY": 0,
      "gridWidth": 6,
      "gridHeight": 4,
      "enabled": 1,
      "enabledName": "显示",
      "items": [],
      "selectedParameters": [
        {
          "deviceType": "1",
          "deviceTypeName": "卫星",
          "deviceCode": "卫星A",
          "deviceName": "卫星A",
          "telemetryCode": "T001",
          "telemetryName": "温度",
          "systemPath": "热控系统",
          "dataItems": []
        }
      ]
    }
  ]
}
```

## 检查及成功导入结果

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "valid": true,
    "widgetCount": 1,
    "parameterCount": 1,
    "itemCount": 0,
    "existingWidgetCount": 2,
    "errors": []
  }
}
```

检查返回`code=200`只表示检查接口正常完成，仍需判断`data.valid`。实际导入成功时`valid=true`、`errors=[]`，`existingWidgetCount`为本次被替换的原组件数量。检查问题最多返回100条，结构检查失败时可能不执行后续关联匹配。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "valid": false,
    "widgetCount": 1,
    "parameterCount": 1,
    "itemCount": 0,
    "existingWidgetCount": 2,
    "errors": ["参数匹配失败：卫星／卫星A／T001"]
  }
}
```
